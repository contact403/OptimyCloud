Politique d'accès AWS du Sprint FinOps

Voici exactement ce que nous demandons pour auditer votre facture AWS. Lisez-la, faites-la valider par votre équipe sécurité, et retirez ce qui vous gêne : c'est vous qui créez le rôle.

Ce que le rôle permet

Lire la facturation (Cost Explorer, Savings Plans, budgets, recommandations AWS), lister les ressources (instances, volumes, bases, clusters, NAT, load balancers, buckets) et lire leurs métriques CloudWatch.

Ce qu'il interdit

Lire le contenu de vos buckets S3, vos secrets, vos paramètres SSM, vos logs, vos tables DynamoDB, le code et les variables d'environnement Lambda, les user-data EC2. Aucune action d'écriture n'est accordée.

Avant l'audit : aucun accès

Le pré-diagnostic gratuit se fait uniquement à partir d'un export Cost Explorer (CSV) que vous nous envoyez. Le rôle ci-dessous n'est créé qu'une fois l'audit commandé et le NDA signé.

1. Politique d'autorisations

Lecture seule, actions listées une par une (pas de ec2:Describe* générique, qui donnerait accès aux user-data). Un bloc Deny explicite ferme en plus l'accès aux données et aux secrets, même si une autre politique attachée au rôle les autorisait.

La facture est analysée via Cost Explorer (y compris la granularité par ressource si vous l'avez activée). Le rôle ne lit pas les fichiers du Cost and Usage Report stockés dans S3 : si vous utilisez le CUR et souhaitez une analyse plus fine, vous pouvez nous transmettre un export vous-même.

2. Relation d'approbation (trust policy)

Seul le compte AWS d'OptimyCloud peut endosser le rôle, et uniquement avec l'identifiant externe (ExternalId) unique que nous vous communiquons au démarrage. Cela protège contre le « confused deputy ».

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::ID_COMPTE_OPTIMYCLOUD:root" },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": { "sts:ExternalId": "VOTRE_EXTERNAL_ID_UNIQUE" }
      }
    }
  ]
}

3. Créer et révoquer le rôle

  1. Console IAM → Rôles → Créer un rôle → « Autre compte AWS », avec l'ID de compte et l'ExternalId que nous vous transmettons.
  2. Créez une politique personnalisée avec le JSON du point 1 et attachez-la au rôle (nom suggéré : OptimyCloudFinOpsAudit).
  3. Envoyez-nous l'ARN du rôle. L'audit démarre, 7 jours ouvrés.
  4. À la fin de l'audit, supprimez le rôle. Vous pouvez aussi le supprimer à tout moment : l'accès s'arrête immédiatement.

Vous avez un doute sur une ligne, ou vous voyez une permission en trop ? Écrivez-nous à alexandre@optimycloud.com : nous corrigeons la politique publiée.
